Title: What should an aquarium environment controller warn you about first?

I'm developing an environment-control project called Sirona. Its Tera branch is for terrariums; Aqua is a separate branch for aquariums. Aqua is at the concept/earlier web-prototype stage: I am not claiming a working aquarium controller or asking anyone to entrust livestock to it.

Before choosing a large feature set, I'd like to hear about the problems that experienced aquarium keepers actually need help detecting.

The current Aqua direction is temperature/flow monitoring and a history of changes, followed only later by verified lighting, filtration and circulation control. The public page uses clearly labelled AI concept art and contains no live aquarium readings.

My questions:

1. Which early warning would have prevented the most trouble in your tank: loss of circulation, abnormal temperature, an equipment-state mismatch, or something else?
2. What should keep running, and what should stop, when a sensor reading disappears or the controller loses its network connection?
3. Would you prefer read-only monitoring first, and what history would help you decide whether to trust later control?

Practical failure stories would be especially useful. Nothing is for sale. Background, if external project links are permitted: https://sirona-living-systems.upbeatcomet6.chatgpt.site/en.html#aqua
